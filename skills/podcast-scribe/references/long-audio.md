# 长音视频

`transcribe` 和 `ingest` 使用同一套自动分片流程，无需为四小时节目另换命令。先读取 [安装与运行](workflow.md) 配置依赖、任务目录和转写密钥；已有完整转写时优先 `import`，省去音频 API 费用。

```sh
bash "$PS_SKILL_ROOT/scripts/run.sh" transcribe '/path/to/four-hour.mp4'
```

## 音频与时间轴

- 本地提取单声道 16 kHz、32 kbps MP3，保留完整录音。四小时转换音频约 57.6 MB；源文件、分片与缓存还会占用额外磁盘空间。
- 用 ffmpeg 解码测量实际时长、检测至少 0.4 秒且低于 −35 dB 的停顿。每片最多 15 分钟，在片尾 30 秒窗口优先选择停顿；找不到停顿时按上限切分。
- 每次上传前再次检查不超过 24 MB。四小时通常为 16–17 片，顺序请求；`chunking_strategy=auto` 仍用于每次请求内部的说话人分离。
- 分片完整覆盖原始时间轴，首尾相接，不重复上传边界音频。转写时间加回片段起点，保留所有有效段落；尾部静音仍计入节目时长。
- 强制切分可能切开字词或句子。边界前后 2 秒涉及的段落标为 `needs_review`，须回听原音核对；不会凭文本自动删重、补词或宣称无遗漏。

## 跨片说话人

每片 API 返回的 `A`、`B` 都是该片自己的标签，不能直接合并。程序优先从已转写片段选择不与其他段落重叠的 2–6 秒独立发言，建立最多 4 个匿名声源参考。之后的请求通过 `known_speaker_names` 与 `known_speaker_references` 携带参考；只有响应明确返回对应参考名时才复用同一个说话人 ID。

参考不足、超过 4 人或接口未匹配时，保留 `chunk-0002:A` 这类片级来源标签，对应段落标为待核对。同一人可能因此暂时有多个 ID；回听确认后通过 `edit` 调整段落的 `speaker_id`，不要依据重复的字母猜测是同一人。参考匹配也可能出错，所以整集 `speakers_confirmed` 保持 `false`，不会猜真实姓名。

## 缓存与恢复

默认缓存位于工作区的 `data/cache/asr/<摘要>/`：

- `manifest.json`：源文件与配置指纹、分片时间轴、状态、校验摘要、参考来源、强制切分位置。
- `audio.mp3`、`chunks/*.mp3`：本地音频与上传分片。
- `chunks/*.json`：每次成功的原始 API 响应及请求上下文。
- `references/*.wav`：匿名声源参考。
- `transcription.json`：全部分片完成后的合并转写。

源文件内容、语言、模型、切片配置和 endpoint 指纹共同决定缓存；endpoint 只存摘要，不把地址中的凭据写入 manifest。与默认官方 endpoint 对应的旧版成功转写缓存仍可复用。

中断或失败后，在原工作区重跑相同命令，保持同一缓存目录；未指定 `--cache` 时继续使用默认目录。程序校验并复用成功分片，只请求尚未完成的部分；原始响应先于后续本地处理保存，避免本地参考提取失败导致重复请求。无语音分片也会缓存；整集均无有效正文则报告无可用转写，不反复调用接口。完整成功缓存可以在没有密钥时复用。

临时网络错误、限流和部分服务端错误每片每次执行最多尝试 3 次；认证错误直接停止。请求超时不代表服务端未计费，因此不能保证重试完全没有额外费用。缓存校验失败时停止，不悄悄用不一致的参考或源文件继续；保留文件后排查，不要清空所有成功响应来重试。

结束时终端给出 manifest 路径、强制边界数和未匹配声源标签数。恢复转写前不要覆盖已有 `episode.json`；若原命令已经成功，继续对该文件校对，确需重新生成草稿则指定新的 `--output`。

## 后续整理与验证范围

按 [分批整理](editing.md) 使用 `status`、`batch` 和增量 `edit` 逐批处理，不要反复把四小时完整 JSON、`raw_text`、缓存响应和历史全部读入模型上下文。全量结构校验、导出与分享由本地程序完成。

自动测试覆盖四小时时间轴的分片与模拟 API 流程、失败续跑、空片缓存、说话人标签冲突、参考参数和短音频 ffmpeg 切片。另已用实际四小时的合成静音音频验证解码、连续分片规划，以及开头、中间和尾部的音频提取。尚未用真实四小时录音进行付费 API 端到端验收；转写质量、强制边界和说话人对应仍需实际回听确认。

接口依据：[OpenAI 文件转写与说话人分离](https://developers.openai.com/api/docs/guides/speech-to-text)。
