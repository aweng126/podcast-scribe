# 长音视频

`transcribe` 与 `ingest` 的音频路径使用同一套自动分片流程，无需为四小时节目另换命令。B站默认先评估字幕，充分时不调用音频 API，只有少量可修补范围时局部转写；规则见 [字幕来源选择](subtitles.md#字幕来源选择)。先按 [安装与运行](workflow.md) 检查实际需要的依赖与任务目录，只有音频路径需要转写密钥；已有完整转写时优先 `import`。

```sh
bash "$PS_SKILL_ROOT/scripts/run.sh" transcribe '/path/to/four-hour.mp4'
```

## 音频与时间轴

- 本地提取单声道 16 kHz、32 kbps MP3，保留完整录音。四小时转换音频约 57.6 MB；源文件、分片与缓存还会占用额外磁盘空间。
- 用 ffmpeg 解码测量实际时长、检测至少 0.4 秒且低于 −35 dB 的停顿。每片最多 15 分钟，在片尾 30 秒窗口优先选择停顿；找不到停顿时按上限切分。
- 每次上传前再次检查不超过 24 MB。四小时通常为 16–17 片，顺序请求；`chunking_strategy=auto` 仍用于每次请求内部的说话人分离。
- 分片完整覆盖原始时间轴，首尾相接，不重复上传边界音频。转写时间加回片段起点，保留所有有效段落；尾部静音仍计入节目时长。
- 强制切分可能切开字词或句子。边界前后 2 秒涉及的段落标为 `needs_review`，供 Agent 整理时优先检查；精准模式再回听并确认疑点；不会凭文本自动删重、补词或宣称无遗漏。

以上是完整音频路径。字幕局部补齐只发送评估返回的完整范围，边界扩展到相交字幕的整条时间；仍需下载并检查完整音频。范围对应片段和身份摘要保存在 `data/cache/<id>/subtitle-repairs/`，付费响应复用下面的 ASR 缓存；局部范围加回原节目起点，不把独立范围内相同标签当成同一人物。

## 跨片说话人

每片 API 返回的 `A`、`B` 都是该片自己的标签，不能直接合并。程序优先从已转写片段选择不与其他段落重叠的 2–6 秒独立发言，建立最多 4 个匿名声源参考。之后的请求通过 `known_speaker_names` 与 `known_speaker_references` 携带参考；只有响应明确返回对应参考名时才复用同一个说话人 ID。

参考不足、超过 4 人或接口未匹配时，保留 `chunk-0002:A` 这类片级来源标签，对应段落标为待核对。同一人可能因此暂时有多个 ID；回听核验，或按 Skill 中用户明确的双人访谈语境归并规则，使用 `edit` 调整段落的 `speaker_id`。语境推定须记录依据及仍需复核的片段，不要依据重复的字母猜测是同一人。参考匹配也可能出错，转写阶段整集 `speakers_confirmed` 保持 `false`。Agent 完成人物对应后按所选模式收尾；自动整理不要求用户逐条回听，也不猜真实姓名。

## 缓存与恢复

默认缓存位于工作区的 `data/cache/asr/<摘要>/`：

- `manifest.json`：源文件与配置指纹、分片时间轴、状态、校验摘要、参考来源、强制切分位置。
- `audio.mp3`、`chunks/*.mp3`：本地音频与上传分片。
- `chunks/*.json`：每次成功的原始 API 响应及请求上下文。
- `references/*.wav`：匿名声源参考。
- `transcription.json`：全部分片完成后的合并转写。
- `usage.json`：最近一次执行的请求与缓存用量报告，后续执行会更新。

源文件内容、语言、模型、切片配置和 endpoint 指纹共同决定缓存；endpoint 只存摘要，不把地址中的凭据写入 manifest。与默认官方 endpoint 对应的旧版成功转写缓存仍可复用。

中断或失败后，在原工作区重跑相同命令，保持同一缓存目录；未指定 `--cache` 时继续使用默认目录。程序校验并复用成功分片，只请求尚未完成的部分；原始响应先于后续本地处理保存，避免本地参考提取失败导致重复请求。无语音分片也会缓存；整集均无有效正文则报告无可用转写，不反复调用接口。完整成功缓存可以在没有密钥时复用；所有分片成功、仅最终合并中断时，也无需密钥或 OpenAI SDK，仍校验音频、参考和响应摘要。只有确需新请求时才创建客户端。媒体已按登记清理时，也可直接复用保留的成功 ASR 结果。

下载音频、转换音频、分片和匿名参考属于工具媒体，按 [存储与清理](storage.md) 管理；用户的原始输入、manifest、成功响应与合并转写保留。部分任务恢复时，只允许重建有明确清理记录的缺失媒体，并验证其内容摘要；仍复用成功响应，不重复成功的 API 请求。未登记的缺失、损坏或摘要不符继续报错，不能把损坏当作已清理。

临时网络错误、限流和部分服务端错误每片每次执行最多尝试 3 次；认证错误直接停止。请求超时不代表服务端未计费，因此不能保证重试完全没有额外费用。缓存校验失败时停止，不悄悄用不一致的参考或源文件继续；保留文件后排查，不要清空所有成功响应来重试。

结束时终端给出 manifest 路径、强制边界数和未匹配声源标签数。恢复转写前不要覆盖已有 `episode.json`；若原命令已经成功，继续对该文件校对，确需重新生成草稿则指定新的 `--output`。

## 转写用量

终端与 `usage.json` 区分本次新增请求和历史缓存复用；生成草稿时也把报告写入 `episode.transcription.usage`，局部字幕补齐会合计各范围，`status` 可查看。报告包含新增分片数及主音频时长、复用片数及其时长、请求尝试与重试次数、失败次数，以及成功响应返回的 token 或时长用量。`submitted_audio_seconds` 按每次请求累计主音频时长（含重试），声源参考另计；这些是提交记录，不等于实际传输完成或服务端计费时长。

`current_run` 只含本次新增请求；`reused_cache` 的响应 usage 属于历史调用，不计为本次新增费用。缺失或无效的响应 usage 单列计数，汇总无法表示时保留 `null`，均不当作零用量。失败尝试的服务端实际用量未知，即使重试成功，成功响应也不能代表全部账单。报告不估算金额；Agent 整理的 token 由宿主平台统计，此处标为未知。`usage.json` 是最近一次运行的记录，不是累计账本，原始成功响应仍保留在分片缓存中。

## 后续整理与验证范围

按 [分批整理](editing.md) 使用 `status`、默认 `batch` 与 `edit --batch --note` 逐批处理。自动模式只跳过本地进度里有效登记的段落；中断后读 `editing-notes` 即可续接主题与疑点，旧 `edited` 不能自动视为已处理。不要反复把四小时完整 JSON、`raw_text`、缓存响应和历史读入模型上下文。整理进度归零后仍需人物、元数据、全篇摘要章节与 `complete`；结构校验、导出与分享由本地程序完成。

自动测试覆盖四小时时间轴的分片与模拟 API 流程、失败续跑、空片缓存、说话人标签冲突、参考参数和短音频 ffmpeg 切片。另已用实际四小时的合成静音音频验证解码、连续分片规划，以及开头、中间和尾部的音频提取。

真实节目 `BV1nB3u6tERu`（约 4 小时 38 分钟）已完成 19 片音频 API 转写、1767 段自动整理和 Markdown／88 页 PDF 导出，检查了时间轴覆盖、结构及 PDF 排版，并验证导出后清理临时媒体、保留付费响应。该验证没有逐句听音，不能据此认定所有字词、强制边界或说话人对应均准确；精确核验仍需回听原音频。

接口依据：[OpenAI 文件转写与说话人分离](https://developers.openai.com/api/docs/guides/speech-to-text)。
