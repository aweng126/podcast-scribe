# 存储与清理

默认由程序管理媒体生命周期，用户只需提供素材。所有路径以任务工作区为基准；清理只处理明确登记为工具下载或生成的媒体，不按目录名、扩展名或通配符推断归属。

## 交付后的自动清理

`export` 同时满足以下条件才自动清理本集已登记的工具媒体：文稿已 `complete`，且**本次** Markdown 和 PDF 均成功生成并通过基础验证。`complete` 本身、过去的导出文件、只导出一种格式或导出失败都不触发清理。基础验证不代替 Agent 对 PDF 中文、分页与段落完整性的渲染检查。

用户明确要求保留媒体时，由 Agent 在导出命令中加 `--keep-media`：

```sh
bash "$PS_SKILL_ROOT/scripts/run.sh" export data/my-episode/episode.json --keep-media
```

该保留选择持续阻止过期回收；下一次不带 `--keep-media` 的完整双格式导出，或显式执行本集 `cleanup --apply`，允许清理本集媒体，但仍尊重其他共用文稿的保留选择。清理范围包括已登记的下载音视频、转换音频、上传分片、匿名声源参考、字幕修补音频及 OCR 派生媒体。活跃缓存与仍由未交付任务共享的媒体保留。

以下内容始终保留：

- 用户提供的原始音视频、字幕及转写文件，即使位于缓存目录中。
- 单集文稿、原始转写、成功 API 响应 JSON、合并转写、manifest 与清理记录。
- 字幕和 OCR 文字缓存、字幕证据与对照报告。
- Markdown、PDF、阅读页、公开投稿文件及可恢复的编辑历史。

## 手动预览与过期回收

查看一集的清理计划，不执行清理：

```sh
bash "$PS_SKILL_ROOT/scripts/run.sh" cleanup data/my-episode/episode.json
```

执行同一计划时加 `--apply`。本集清理仍要求当前稿有完整的 Markdown/PDF 交付记录，且两个导出文件的内容摘要与记录匹配；缺失、改动或稿件更新后需重新完整导出。命令会报告可清理项与保留原因；不要为腾空间直接删除整个 `data/cache/`，其中包含可复用的付费响应与文字证据。

预览 7 天未使用媒体的回收范围：

```sh
bash "$PS_SKILL_ROOT/scripts/run.sh" cleanup --expired --cache data/cache --older-than-days 7
```

加 `--apply` 执行。每次新媒体处理也会自动尝试同样的 7 天回收；活跃缓存、显式保留媒体和仍由未交付任务共享的媒体不会被回收。中断、失败或未完成任务不会因导出而清理，但单一任务的媒体在 7 天未使用后可回收，续跑时按记录重建；共享未交付任务继续保留。回收依据登记的使用记录，不把文件修改时间直接当作任务已结束。

旧版未登记的媒体保守跳过；不能用通配符批量删除来补做迁移。保留文件不会阻断新任务，Agent 无需增加用户确认或必填参数。

## 编辑历史与恢复

编辑历史保留最初版本、最近 10 个版本及已完成、已发布的关键版本为 JSON。其余版本无损压缩为 `.json.gz`；程序校验解压后的内容与原文件相同，才移除重复的未压缩副本。压缩不丢失原文、原始人物标签或修订记录。

长稿整理期间每 10 次修订维护一次，完成、成功双格式导出和显式清理时也会维护；因此处理中可能暂时多保留最近的若干 JSON，避免每个小批次都重读整套历史。

需查看旧版本时按需解压到另一个文件，再读取或比较；不要覆盖当前 `episode.json`。重跑与整理仍从现稿的 `status`、`batch` 和 `editing-notes` 继续，无需展开全部历史。

媒体清理不删除成功 ASR 结果。完整成功缓存无需转换音频或上传分片即可复用；源文件仍用于核验身份，B站原下载已清理且需要重建草稿时可能重新下载。已有文稿直接继续编辑或导出，无需重建。部分任务只重建明确登记为已清理的媒体，并校验内容摘要，继续复用成功响应。普通缺失、损坏或校验不符仍报错，不以重新调用成功 API 请求掩盖问题；恢复细节见 [长音视频](long-audio.md#缓存与恢复)。
