# 听稿 · Podcast Scribe

用户只需说“使用 podcast-scribe”并提供链接或文件。直接按以下默认值完成任务，不要求用户再次指定完整转写、时间戳、摘要、格式、路径、分片或解释器：按中文阅读习惯整理并保留原意，保留全部对话、说话人与时间戳，生成摘要、章节、Markdown 和 PDF；未知系列为 `inbox` / “待归类”；文稿保存在任务工作区 `data/<id>/episode.json`，导出文件保存在 `output/<id>/`。用户明确给出不同要求时覆盖相应默认值。离线阅读页与社区分享均为额外选项，不主动公开文稿。

## 处理模式

默认使用**自动模式**（`review.mode=auto`）：Agent 完成全文整理、人物对应、摘要和章节后直接交付，不要求用户逐段手动校对。结合上下文与可用字幕处理疑点，证据不足时保留原意，不补造词句；普通识别歧义记录在本地整理笔记，不把“待核对”注释插入阅读稿。确实没有可辨文字时可写“听不清”，不编造缺失内容。默认不执行全片 OCR 或逐句回听。

用户明确要求“精准模式”时设置 `review.mode=precise`，再做字幕/OCR、原音核验；仍无法判断的片段汇总为带时间戳的清单，请用户手动确认。已有稿件通过 `edit` 切换模式，复用转写与字幕缓存。自动整理、用户明确接受当前稿、依据来源精校分别记录为 `automated`、`user_accepted`、`source_checked`，见 [模式与完成状态](references/schema.md#校对状态)。

## 运行入口

先区分 **Skill 安装目录**（本文件所在目录）与 **任务工作区**（用户本次保存文稿的目录）。由 Agent 将 `PS_SKILL_ROOT` 设为本文件所在目录的绝对路径，并从任务工作区调用 `bash "$PS_SKILL_ROOT/scripts/run.sh" ...`。该入口自动选择可用 Python 与已有虚拟环境；用户无需提供解释器路径。不要为了调用工具切换到 Skill 安装目录；相对输入、缓存和输出路径均以当前任务工作区为基准。

首次使用按 [安装与运行工作流](references/workflow.md) 检查能力；缺少依赖时由 Agent 执行 `bash "$PS_SKILL_ROOT/scripts/run.sh" setup`，已有环境直接复用。普通命令和 `doctor` 不自行安装。已有转写、Markdown 和阅读站流程无需 API；音频转写需要运行环境中的 `OPENAI_API_KEY`。缺少密钥、访问权限或必须明确的输入时说明实际阻塞；不要猜测密钥，也不要把可采用默认值的选项交给用户逐项填写。

## 执行流程

1. 识别输入并采用默认值，复用对话中已给定的选择。先检查是否已有匹配的单集文稿：已有稿件直接从 `status` 续编，不重复下载、转写或导入；未完成的音频任务复用缓存。系列未知时保留“待归类”，不要把 UP 主自动当成系列。B站链接带分 P 时按指定单 P 处理；实际存在无法确定的输入范围时才询问。
2. 按本次输入和输出运行 `doctor --require ...`（如已有转写为 `import markdown pdf`，新 B站任务为 `ingest markdown pdf`）。退出码非零时按报告补齐对应环境；不要因默认 PDF 暂不可用而假称已经完成。B站链接用 `ingest`，程序内部检查来源；仅需查看元数据时用 `inspect`。本地音视频用 `transcribe`；已有 JSON/SRT/VTT 用 `import`。省略可推导的 ID、标题和输出路径，让 CLI 使用默认值。这些命令只生成未经整理的草稿，之后必须继续执行整理与导出。音频转写当前接入 OpenAI，音频会发送到配置的 API endpoint；已有转写导入和导出均本地运行。不要把 API key 写进命令字面量、JSON、日志或文稿。本地前置检查成功不代表网络或模型权限可用。
3. 匿名访问受限时，按 [访问受限时的处理](references/workflow.md#b站访问受限时)，请用户在浏览器正常完成登录或验证码，并授权使用指定浏览器登录态或本地 cookies 文件；已有明确授权时复用。由 Agent 先用 `inspect` 验证，再继续原任务，无需用户配置命令。不得自行读取或轮试其他浏览器，不将凭据写入文稿或日志。授权重试仍失败或只能试看时停止，保留诊断并使用用户提供的本地素材；不能保证解决 412。字幕仅辅助核对，没有人物标签时按第 5 步结合节目结构和上下文处理归属，不把标题或简介冒充完整对话。
4. 利用已有字幕辅助整理：新 B站 `ingest` 自动采集并对照，已有稿件使用 `check-subtitles`，本地字幕用 `--file`。自动模式无独立轨时继续整理；精准模式或用户明确要求画面字幕核验时，按 [字幕辅助核验](references/subtitles.md) 先验证 OCR 短片与区域，再提取完整范围。由 Agent 选择参数并复用已授权登录态。用 `subtitle-batch` 分批读取相关差异；字幕一致和 OCR 置信度不是逐句听音证明。报告过期时重新对照，不重做成功 ASR。用 `status` 查看进度，按 [分批整理](references/editing.md) 用 `batch` 读取正文，默认每批 6000 字符，生成增量 edits JSON，通过 `edit --batch` 保存。不要反复读取全文、原始响应或历史；按需读取 `--raw`。逐段保留事实、否定、数字、观点、论据和例子，只清理不承载含义的重复、改善标点和分段。同一人物连续发言按话轮阅读，真正插话仍单列。全部批次须覆盖原始 ID 与顺序；原始转写不可改。用户仅要转录草稿时按其范围交付。
5. 用覆盖全篇的批次笔记生成摘要与有实际内容意义的章节，保留关键事实和段落 ID，必要时回读对应批次，章节必须定位到真实段落。人物先使用匿名标签；需要实名时，查找原节目官方说明、文字记录或明确的自我介绍，并将具体问答与来源核对，更新姓名、角色和 `references`；未能核实时保留匿名标签；精准模式可请用户确认。不用面孔或声纹猜真实身份。用户或节目资料已明确为双人访谈时，以采访者、受访者为人物集合，结合问答关系、连续发言与上下文归并碎片化声源标签；自动模式按语境推定并记录依据，短应答或抢话的歧义保留在本地笔记中；精准模式仍有疑点则保留 `needs_review` 供确认，不把语境推定当作逐句听音。重新分配后按 [数据与编辑约定](references/schema.md) 移除无引用的旧标签；原始归属保留在历史中。多人节目按实际参与者处理。长音频的切片、缓存和参考声源规则见 [长音视频](references/long-audio.md)；参考音频辅助对应不等于已核对，不能直接拼接独立分块的 Speaker 1。输入若是剪辑片段，明确其时长与范围，不声称已处理完整节目。
6. 按 [校对状态约定](references/schema.md) 逐段记录整理结果。自动模式全文整理完毕，人物标签、摘要与章节有效后运行 `complete`，记录 `basis=automated`，直接交付；它不替代 Agent 的全文整理，不能对未经处理的原始转写运行。精准模式逐段核验，未解疑点请用户确认，完成后用 `complete --basis source_checked`；用户明确表示接受当前稿、无需继续核对时，用 `complete --basis user_accepted` 记录其决定，不称为听音确认。随后 `validate`、`export`，默认生成 Markdown 和 PDF 到 `output/<id>/`。抽查开头、中间、结尾与人物切换；PDF 渲染检查中文、分页与段落完整性。文首简洁说明完成方式，阅读稿不重复显示通用校对标签。
7. 用户需要离线页面时才运行 `site --preview`。需要自行部署站点时，按 [工作流](references/workflow.md) 使用本地 `publish`、重新导出和正式构建；`publish` 只修改本地状态，不表示线上已发布。
8. 完成所选模式并交付本地文件后，主动邀请分享一次，例如：“是否愿意将这篇文稿分享到 Podcast Scribe 社区阅读站？可以仅保存在本地；如果愿意，请告诉我公开署名。”批量任务合并询问；已明确仅本地或不分享时尊重选择，已要求分享时直接继续，不回复不视为同意。仅完成原始转录时，说明还需完成整理才可投稿；失败、未完成任务及演示内容不发分享邀请。
9. 用户同意社区分享后，读取 [分享投稿](references/sharing.md)，检查已完成所选模式并确认公开署名。自动模式不另加人工精校门槛；投稿保留真实的完成方式。缺少署名时只补问署名。`share` 生成公开 JSON 和 Issue 表单链接，不上传、不提交 Issue，也不修改本地状态。给出文件和链接，由用户检查后上传提交；已有授权无需重复确认。Issue 与附件公开可读，收录仍由维护者审核。只有获得实际 Issue 或部署结果时，才能分别称为“已投稿”或“已上线”。演示记录不能作为真实节目投稿。

## 完成标准

- 给出实际产物路径及完成方式；自动模式直接交付，精准模式列明仍需用户确认的疑点。
- 原始转写、人工修订、输出文件相互可追溯。重跑不得覆盖已存在的校对稿；使用 `edit` 修改，或为新结果指定新路径。
- 如果只完成基础程序或演示，不声称用户的源视频已转写成功。
- 读取接口规范或更换服务时，核实官方文档；现有提供商限制见 [工作流](references/workflow.md)。
