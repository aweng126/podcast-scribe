# 听稿 · Podcast Scribe

用户只需提供 Skill 名称和链接或文件。默认按中文阅读习惯忠实整理全部对话，保留说话人与时间戳，生成摘要、章节、Markdown 和 PDF。文稿保存为任务工作区的 `data/<id>/episode.json`，导出至 `output/<id>/`；路径、解释器、分片及格式由 Agent 采用默认值。用户的明确要求优先，离线页面和公开分享均为可选项。

## 运行与模式

将 `PS_SKILL_ROOT` 设为本文件所在目录的绝对路径，从**任务工作区**调用 `bash "$PS_SKILL_ROOT/scripts/run.sh" ...`；不要切换到 Skill 安装目录保存用户素材。首次运行或环境报错时读取 [安装与运行](references/workflow.md)，按所需能力运行 `doctor`，缺少依赖时执行 `setup` 后复查。字幕和已有转写路径无需转写密钥；实际需要音频 API 时才补齐对应条件。

默认**自动模式**：Agent 全文整理后直接交付，无需用户逐段核对；按上下文和可用来源处理歧义，保留原意，普通疑点记在本地笔记，不向阅读稿插入通用“待核对”标签。不默认全片 OCR 或逐句回听，不补造听不清的文字。

用户明确选择**精准模式**时使用 `review.mode=precise`，依来源逐段核验并将未解疑点交给用户。新 B站任务的默认来源 `auto` 会采用独立音频；已有稿切换模式复用现稿与缓存，见 [模式与完成依据](references/schema.md#校对状态)。

## 执行流程

1. **识别与续接。** 先检查匹配的现稿，已有稿从 `status` 继续，未完成音频任务复用缓存，不重复下载、转写或导入。B站按指定单 P 处理；范围确实不明时再问。按 [系列归属](references/series.md) 查节目资料与目录，明确归属用 `classify` 保存依据；无法确认则保留 `inbox` / “未分类”，继续交付。
2. **取得草稿。** 新 B站任务按实际输出检查能力（默认 `doctor --require ingest markdown pdf`），再使用 `ingest`：默认字幕充分时直接采用、少量缺口局部补齐，否则转写音频。用户指定字幕时不回退到付费音频，来源判断详见 [字幕选择](references/subtitles.md#字幕来源选择)。本地音视频用 `transcribe`，已有 JSON/SRT/VTT 用 `import`，只查元数据用 `inspect`。入口输出均为待整理草稿；音频路径会发送素材到配置的 OpenAI endpoint 并产生 API 费用。长音频或恢复任务读取 [切片与缓存](references/long-audio.md)。
3. **处理访问限制。** 匿名请求受限时按 [B站访问受限](references/workflow.md#b站访问受限时) 处理，复用已明确授权的浏览器或 cookies；未授权时请用户正常登录并指定授权来源。先用 `inspect` 验证，不轮试其他浏览器，不导出凭据。授权重试仍失败或只能试看时停止，保留诊断，改用用户提供的本地素材。
4. **逐批整理。** 读取 [分批整理](references/editing.md)，使用 `status`、默认 `batch`、`edit --batch --note` 与 `editing-notes` 续接。逐段保留事实、否定、数字、论据和例子；显式登记实际处理的段落，保留原始 ID、顺序、时间戳与 `raw_text`。默认不反复读取全文和历史，疑点才按范围读取原文。有独立字幕证据或用户要求画面核验时读取 [字幕辅助核验](references/subtitles.md)；同源字幕自我匹配不能证明已独立核验，字幕核验也不代表理解完整画面。
5. **人物与收尾。** 按 [人物归属](references/schema.md#人物归属) 核实人物资料并结合问答对应发言；明确双人访谈时按采访者、受访者归并碎片标签，记录语境判断依据，不凭面孔、声纹猜身份。证据不足以对应时保留匿名或未知并说明阻塞。基于覆盖全文的有效批次笔记生成摘要和章节，章节锚定真实段落，回读必要片段检查衔接。剪辑素材须说明实际范围。
6. **完成与交付。** `batch.done` 不等于整集完成。全文整理、人物、摘要和章节有效后，自动模式运行 `complete`；精准模式按 [完成依据](references/schema.md#校对状态) 使用 `source_checked`，用户明确接受当前稿才用 `user_accepted`。随后 `validate`、`export`，核验段落完整性并渲染检查 PDF 的中文、分页及人物切换；两种格式都成功才称默认交付完成。程序在合格的完整交付后自动清理工具媒体，用户要求保留时传 `--keep-media`；其他清理需求读 [存储与清理](references/storage.md)。
7. **可选阅读页。** 用户需要本地页面才运行 `site --preview`。自行部署按 [运行工作流](references/workflow.md) 操作；`publish` 仅改变本地状态，不表示已上线。
8. **可选分享。** 完成交付后邀请分享一次；已拒绝时尊重选择，已同意时直接继续，未回复不视为同意。读取 [分享投稿](references/sharing.md)，沿用已确认公开署名，仅在缺少时补问。`share` 只生成公开 JSON 和预填 Issue 链接，不上传或投稿。交付两者的可点击链接及“上传 JSON → 检查信息 → 勾选确认并提交”步骤，由用户网页提交；不能把材料已准备称为已投稿或已上线。失败、未完成稿和演示记录不邀请投稿。

## 完成标准

- 提供实际产物链接与真实完成方式；原始转写、编辑和输出可追溯。
- 现稿通过 `edit` 修改，重跑不覆盖已有稿；未完成时说明具体剩余事项，不声称全文已整理或默认格式已交付。
- 密钥与浏览器凭据不进入命令、文稿或日志；读取新接口规范或更换服务时核实官方文档。
