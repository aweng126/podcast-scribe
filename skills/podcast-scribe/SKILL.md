# 听稿 · Podcast Scribe

听稿将播客与访谈整理成可阅读、可检索、可导出的完整文稿。本 Skill 的默认成品是：保留完整对话的整理稿、摘要、章节、说话人和时间戳。默认导出 Markdown 与 PDF；用户可只选择一种。离线阅读页与社区分享均为额外选项，不主动公开文稿。

## 运行入口

先区分 **Skill 安装目录**（本文件所在目录）与 **任务工作区**（用户本次保存文稿的目录）。从任务工作区运行安装目录中的绝对脚本入口：`"$PS_SKILL_ROOT/.venv/bin/python" "$PS_SKILL_ROOT/scripts/podcast_scribe.py" --help`，其中 `PS_SKILL_ROOT` 是本文件所在目录的绝对路径。不要为了调用工具切换到 Skill 安装目录；相对输入、缓存和输出路径均以当前任务工作区为基准。未指定产物路径时，使用工作区的 `data/` 与 `output/`；具体单集 JSON 仍须传 `--output`。

首次使用按 [安装与运行工作流](references/workflow.md) 创建环境、检查能力；已有环境直接复用。仅导入转写、整理和输出 Markdown/阅读站时，可用 Python 3.10+ 解释器执行同一脚本，无需 API 或第三方包。需要音频转写或 PDF 时安装项目依赖。

## 执行流程

1. 确定输入、系列与输出格式。复用对话中已给定的选择；默认中文完整整理稿、Markdown + PDF。系列未知时暂放“待归类”，不要把 UP 主自动当成系列。B站多 P 需处理指定单 P。
2. 按本次输入和输出运行 `doctor --require ...`（如 `import markdown site`，或 `ingest markdown pdf`）。退出码非零时按报告补齐对应环境，或在用户认可的输出范围内选择可用能力；本地前置检查成功不代表网络或模型权限可用。B站链接先 `inspect`，可读时 `ingest`；本地文件用 `transcribe`；已有 JSON/SRT/VTT 用 `import`。这些命令只生成未经整理的草稿。音频转写当前接入 OpenAI，音频会发送到配置的 API endpoint；已有转写导入和导出均本地运行。不要把 API key 写进命令字面量、JSON、日志或文稿。
3. 网页受限时，程序可尝试正常公开播放 API 与接口提供的有限备用音频地址；API 也拒绝访问、需要登录或只返回试看时，说明实际阻塞并保留诊断，请用户提供本地音视频路径或自行处理登录。不得把标题、简介或搜索片段冒充完整对话。字幕没有说话人标签时标为待确认，不根据交替出现的文字猜人物。
4. 读取生成的单集 JSON，按 [数据与编辑约定](references/schema.md) 生成 edits JSON，再运行 `edit`。逐段保留事实、否定、数字、观点、论据和例子，只清理不承载含义的口头重复，改善标点和分段。同一人物连续发言按一个话轮阅读，姓名与起始时间只展示一次；不要把 ASR 切片当作段落，整理时连读相邻切片，清理无意义的边界重复和断句。真正的插话仍单列，长发言按语义分段。必须处理全部段落，不截取开头冒充整集。长文可分批编辑，但必须保留原始 ID、顺序与全篇覆盖。原始转写不可改；听不清处明确标记，不补造。
5. 生成摘要与有实际内容意义的章节，章节必须定位到真实段落。人物先使用匿名标签；需要实名时，主动查找原节目官方说明、文字记录或明确的自我介绍，并将当前片段的具体问答与来源相互核对。身份确认后更新姓名与角色，把依据加入 `references`；未能核实才保留匿名标签或请用户确认。不用面孔或声纹猜真实身份。姓名核实不等于每个重叠发言都已校对；跨集标签独立，超长音频不能直接拼接独立分块的 Speaker 1。输入若是剪辑片段，明确其时长与范围，不声称已处理完整节目。
6. 按 [校对状态约定](references/schema.md) 逐段记录 `review_status`：整理但未核对为 `edited`，有疑点为 `needs_review`，实际核对后才为 `reviewed`。所有段落均已核对后才能确认整集内容校对完成，不能只设全局开关。`validate` 后 `export` 用户选择的格式。抽查开头、中间、结尾与人物切换；PDF 必须渲染检查中文、分页与段落完整性。程序的结构验证不等于语义校对；未经验证的正确性不要标记为已确认。
7. 用户需要离线页面时才运行 `site --preview`。需要自行部署站点时，按 [工作流](references/workflow.md) 使用本地 `publish`、重新导出和正式构建；`publish` 只修改本地状态，不表示线上已发布。
8. 每次转录或文稿整理任务完成后，先交付本地文件并说明校对状态，再主动邀请分享一次，例如：“是否愿意将这篇文稿分享到 Podcast Scribe 社区阅读站？可以仅保存在本地；如果愿意，请告诉我公开署名。”批量任务合并询问一次，让用户选择要分享的文稿；不要在中间切片或单个命令完成时反复邀请。用户已明确仅本地或不分享时尊重选择，已要求分享时直接继续；不回复不视为同意。仅完成转录草稿时，邀请须说明完成校对后才能投稿，不提前运行 `share`。失败、未完成的任务及演示内容不发分享邀请。
9. 用户接受邀请或主动要求社区分享后，读取 [分享投稿](references/sharing.md)，检查全文与人物已校对，并确认公开署名。缺少署名时只补问署名，不猜测姓名。`share` 生成仅含公开字段的 JSON 和 Issue 表单链接，不上传文件、不提交 Issue，也不修改本地状态。给出文件和链接，由用户检查后上传提交；已有授权覆盖的公开意图无需重复确认。Issue 与附件在公共仓库即可被他人读取，收录仍需维护者审核。只有获得实际 Issue 或部署结果时，才能分别称为“已投稿”或“已上线”。演示记录不能作为真实节目投稿。

## 完成标准

- 给出实际产出的文稿/预览路径，说明是否草稿、哪些人物尚待确认。
- 原始转写、人工修订、输出文件相互可追溯。重跑不得覆盖已存在的校对稿；使用 `edit` 修改，或为新结果指定新路径。
- 如果只完成基础程序或演示，不声称用户的源视频已转写成功。
- 读取接口规范或更换服务时，核实官方文档；现有提供商限制见 [工作流](references/workflow.md)。
